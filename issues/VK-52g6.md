## Description
## USER INTENT
The owner needs a cryptographic boundary ensuring agents can advise but can never impersonate the human or promote through a blocked gate.

Observable outcome: the owner can run the declared command, inspect or display its output, and verify that the implementation returns the declared result, stores its immutable artifact, and emits the corresponding hash-verified event.

## Context (Embedded)
Implement the local owner key ceremony and trust manifest. Private key lives outside `GAUNTLET_DATA_ROOT`, normally `~/.gauntlet/owner-key.pem`, mode 0600; public key/key ID live in an immutable local trust manifest. Owner CLI signs a canonical envelope of subject IDs, decision vocabulary, reason, policy version, prior snapshot hash, timestamp, nonce, review mode, and reveal-log hash. Services verify signature, key ID, nonce, timestamp window, vocabulary, policy disposition, and subject hash. Agent/MCP capability context structurally sets actor.kind=agent and ignores client-supplied human identity, owner key ID, or signature claims. Owner-only actions include decision vocabulary, documented FAIL exceptions, multi-axis and sub-200 Verified exceptions, family renewal/budget change, quarantine release, policy change, material data-cost approval, and live eligibility declaration. Phase 1 exposes no live-activation command.

Phase 1 global constraints:
- Local single-owner operation only; no public API, multi-tenant access, daemon, social publishing, or order placement.
- Immutable local evidence and replayability govern implementation choices.
- Unknown or unregistered inputs are gate-critical failures.
- Failures return machine-readable errors and never fabricate a score or silently substitute data.
- No SQLite or other database engine dependency is permitted; canonical JSON/JSONL and Parquet projections are fully regenerable.

## OUT OF SCOPE
- Recommendation generation: advisory only and outside this story.
- Remote owner authentication or tunneling: future phase.
- Live order placement or real-money exposure: Phase 1 remains RED with zero real-money exposure.
- Public API access or public performance claims: explicit business non-goals.

### Acceptance Criteria (story contract)
1. Local bootstrap creates an Ed25519 key with mode 0600 and an immutable trust manifest outside GAUNTLET_DATA_ROOT.
2. A valid signature records actor.kind=human and writes a new `owner-decisions/<action-id>.json` extension linked to the exact prior snapshot hash without changing snapshot bytes.
3. Invalid, expired, replayed nonce, wrong-subject, wrong-key, missing trust manifest, or otherwise unverifiable authorization fails closed and leaves snapshot/gate state unchanged.
4. MCP/agent capability context structurally sets actor.kind=agent and cannot claim human identity or supply a private key/token through arguments, environment pass-through, report fields, or events.
5. Vocabulary is restricted to CONTINUE, HOLD, QUARANTINE, RELEASE, KILL, RENEW, PROMOTE, OVERRIDE and policy compatibility is enforced.
6. BLOCKED can never be promoted; permitted FAIL exceptions require completed forensics and a separately ledgered exception with unchanged computed results.
7. Authorization-failure events contain only verifier, supplied key ID, failure class, subject, and nonce/timestamp bounds—no key material.

## Testing Requirements
- Unit: Test key permissions, canonical envelopes, signature/nonce/timestamp/vocabulary checks, and capability-context rejection.
- Integration tests: MANDATORY (no mocks). Using a real temporary Ed25519 key, sign and record one action, replay it, submit a wrong-subject signature, and submit an MCP human claim; verify only the first changes state.
- Commands to run: `uv run pytest tests/auth/test_owner_boundary.py`.
