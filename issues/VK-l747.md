## Description
## USER INTENT
The owner needs every historical or external metric independently checked against source-provenanced recomputation before it can influence evidence.

Observable outcome: the owner can run the declared command, inspect or display its output, and verify that the implementation returns the declared result, stores its immutable artifact, and emits the corresponding hash-verified event.

## Context (Embedded)
Implement claim-versus-realized reconciliation. Inputs are claimed metric/capability, source provenance, independently recomputed metric and source, predeclared materiality tolerance and policy version, differences, and pass/fail verdict. Unverifiable claims cannot support promotion. Reconciliation covers the founding dex_winner Sharpe collapse pattern: no claimed metric is accepted without source provenance, recalculation where source data permits, execution replay, and comparison against realized evidence.

Phase 1 global constraints:
- Local single-owner operation only; no public API, multi-tenant access, daemon, social publishing, or order placement.
- Immutable local evidence and replayability govern implementation choices.
- Unknown or unregistered inputs are gate-critical failures.
- Failures return machine-readable errors and never fabricate a score or silently substitute data.
- No SQLite or other database engine dependency is permitted; canonical JSON/JSONL and Parquet projections are fully regenerable.

## OUT OF SCOPE
- Collecting or decomposing the claim: upstream Scarlett/audit work.
- Promoting a reconciled result: decision-engine story.
- Live order placement or real-money exposure: Phase 1 remains RED with zero real-money exposure.
- Public API access or public performance claims: explicit business non-goals.

### Acceptance Criteria (story contract)
1. Report claimed value, recomputed value, per-metric difference, tolerance band, both provenances, policy version, and verdict.
2. Tolerance is declared before reconciliation and cannot be selected after seeing the difference.
3. Source data that does not permit recalculation yields an unverifiable claim that cannot support promotion.
4. Execution replay discrepancies are reconciled against realized evidence, not overwritten.
5. Every input and output hash is recorded for replay.
6. A passing reconciliation does not itself promote a candidate.

## Testing Requirements

- Commands to run: `uv run pytest tests/lab/test_reconciliation.py`.
